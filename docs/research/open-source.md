# Open-source / reverse-engineering resources for the Microsoft Teams internal APIs

Research for **kelma** (native Rust Teams client for Linux, GPL-3.0). Compiled 2026-11-18 from a local clone of purple-teams (`~/.local/src/purple-teams`, HEAD 76d8b3a, 2026-11-07) plus shallow clones of ~35 other projects (under `scratchpad/research/repos/`) and GitHub code search. Everything marked "verified" below means the source project says it checked the call against a live tenant; "documented-only" means it appears in a source file or HAR capture but its author never exercised it. Nothing here was executed by me against a live tenant.

Auth shorthand used throughout:

| Tag | Meaning |
|---|---|
| **SKYPE** | chat service style: header `Authentication: skypetoken=<skypetoken>` (note: `Authentication`, not `Authorization`) |
| **XSKYPE** | middle-tier style: header `x-skypetoken: <skypetoken>` |
| **SPACES** | AAD bearer for `https://api.spaces.skype.com/.default` (same one used for authz) |
| **CSA** | AAD bearer for `https://chatsvcagg.teams.microsoft.com/.default` |
| **PRES** | AAD bearer for `https://presence.teams.microsoft.com/.default` |
| **SUB** | AAD bearer for substrate: `https://substrate.office.com/.default` or `https://outlook.office.com/search/.default` / `SubstrateSearch-Internal.ReadWrite` |
| **IC3** | AAD bearer for `https://ic3.teams.office.com/.default` (call control, and Squads uses it directly against chatsvc) |
| **GRAPH** | AAD bearer for `https://graph.microsoft.com/.default` (the Teams client id 1fec8e78 is pre-authorised for a limited scope set, see "Graph scopes") |
| **AMS** | `Authorization: skype_token <skypetoken>` |

License column legend (kelma is GPL-3.0): **OK** = permissive (MIT/ISC/Apache-2.0/BSD) or GPL-3.0, code may be copied with notice; **OK (MPL)** = MPL-2.0, file-level copyleft, combinable with GPL-3 via MPL section 3.3; **ONE-WAY** = AGPL-3.0, can be combined into GPL-3 work but the combined work then also carries the AGPL network clause, so prefer to reimplement from the endpoint facts; **NO** = no licence file / NOASSERTION / non-free terms: read for protocol facts only, do not copy code. Endpoint URLs and JSON field names are facts, so reimplementing them is safe even from a NO project.

### teams-for-linux: insights (it is a wrapper, not an API client)
* It reuses the **web app's own tokens**: `app/browser/tools/reactHandler.js` walks Teams' React service tree (`authenticationService._coreAuthService._authProvider.acquireToken('https://graph.microsoft.com')`) and the main process caches the result. Also ships a `_tokenCache` shim (`tokenCache.js`, Electron `safeStorage`) so the web app can silent-refresh. Not applicable to a native client, but it confirms Graph token reuse via the Teams client id.
* Presence set: `PUT https://presence.teams.microsoft.com/v1/me/forceavailability/` with `{availability, activity?}`, and "Offline" needs `activity: "OffWork"` (`app/control/teamsControlService.js`).
* Call state comes from the web app's internal toast/React state (`activityHub.js`: `incoming-call-created`, `call-connected`, `meeting-started`; scenario names `incoming_call`, `incoming_pstn_call`, `incoming_call_queue_call`), not from a documented API. Useful as a list of call kinds kelma's push handler should recognise.
* Other ideas worth stealing at the product level: D-Bus control surface, MQTT status publishing, tray unread badge, idle monitor feeding `reportmyactivity`, Intune SSO.

## 2. Foundations that matter for every feature

### 2.1 Hosts and discovery
Authz response (`POST https://teams.microsoft.com/api/authsvc/v1.0/authz`, `Authorization: Bearer <SPACES>`, empty body) returns `tokens.skypeToken`, `region`, `partition`, `userRegion`, `regionGtms{...}`, `regionSettings`, `licenseDetails`. `regionGtms` keys seen (fossteams `pkg/authz.go`, mautrix OpenAPI, ost, tinyclient fixture):

* `chatService` (`https://<geo>.ng.msg.teams.microsoft.com`), `chatServiceAfd` (`https://teams.microsoft.com/api/chatsvc/<geo>`), `chatServiceAggregator` / `chatSvcAggAfd` (CSA, `https://teams.microsoft.com/api/csa/<geo>`), `middleTier` (`https://teams.microsoft.com/api/mt/part/<partition>` or `/api/mt/<geo>`), `teamsAndChannelsService`, `teamsAndChannelsProvisioningService`, `appsDataLayerService`, `userProfileService`, `userEntitlementService`, `userIntelligenceService`, `mtImageService`, `drad`.
* `ams` / `amsV2` (`https://<geo>-prod.asyncgw.teams.microsoft.com`, also `https://<geo>-api.asm.skype.com`), `urlp` / `urlpV2` (`https://urlp.asm.skype.com`), `search` (`https://<geo>-prod.asyncgw.teams.microsoft.com/msgsearch`) and `searchService`, `unifiedPresence` (`https://presence.teams.microsoft.com`), `presenceUPS` (`https://teams.microsoft.com/ups/<geo>`), `mcpService` (`https://teams.microsoft.com/api/mcps/<geo>`).
* `calling_conversationServiceUrl` (`https://api-<geo>.flightproxy.teams.microsoft.com/api/v2/epconv`), `calling_callControllerServiceUrl`, `calling_callStoreUrl` (`.../api/v2/ep/api.userstore.skype.com/`), `calling_registrarUrl`, `calling_potentialCallRequestUrl`, `calling_udpTransportUrl`, `calling_keyDistributionUrl`, `calling_sharedLineOptionsUrl`, `calling_uploadLogRequestUrl`, plus `callingS2S_*` (server-to-server, not for clients).
* The web client moved to `https://teams.cloud.microsoft/...`; every `teams.microsoft.com/api/{chatsvc,csa,mt}/...` path also exists on `teams.cloud.microsoft` (rusty-teams, sigcli, Maxim use it). Region is auto-discovered; never hardcode (xteams, Jezza/ic3 notes `de` maps to `emea`, geo `at`/`eu` observed in chatsvcAfd).
* Call-control requests need headers `ms-teams-partition`, `ms-teams-region`, `ms-teams-ring: general`, `x-ms-migration: True`, `x-microsoft-skype-client: SkypeSpaces/1415/<platform>/TsCallingVersion=...` (ost, mautrix, teams-lite).

### 2.3 Graph scopes available to the Teams client id (decoded `scp`, better-teams `docs/graph-allowlist.txt`, 2026-09-28)
Granted: Calendars.ReadWrite(.Shared), Files.ReadWrite.All, Sites.ReadWrite.All, Notes.ReadWrite.All, Tasks.ReadWrite, Group.Read.All, Team.ReadBasic.All, Channel.ReadBasic.All, Channel.Create, ChannelMessage.Read.All, ChannelMessage.Send, ChatMessage.Send, TeamMember.ReadWrite.All, TeamsTab.ReadWrite.All, AppCatalog.Read.All, TeamsAppInstallation.ReadForTeam, People.Read, User.ReadBasic.All (35 names total).
**Not** granted (live 403): any `Presence.*`, `Chat.Read/ReadBasic/ReadWrite/Create`, `ChatMember.*`, `OnlineMeetings.*`, `Team.Create`, `ChannelSettings.*`, `Channel.Delete.All`, `TeamsAppInstallation.*ForUser`, `User.Read.All`, `TeamworkTag.*`. Consequence: **do not plan on Graph for presence, chats, pins, hide, members or meetings by id**; use the Teams services below.

### 2.4 Message addressing facts reused by many features
* 1:1 chat id is derivable with no call: `19:<oidLow>_<oidHigh>@unq.gbl.spaces` with both AAD object ids lowercased and sorted (Maxim, mautrix, better-teams, Jezza). Cross-tenant/personal-work 1:1 is `19:uni01_<52 base32>@thread.v2`.
* Channel thread replies are addressed `<channelId>;messageid=<rootId>` (percent-encode `;` and `=` for sends: `%3Bmessageid%3D`); edits/deletes/reactions on a reply use the plain channel id (Jezza §9.21, verified for sends).
* Message id = `OriginalArrivalTime` (ms epoch) from the POST answer or the `Location` header, not the echoed `clientmessageid`.
* MRIs: `8:orgid:<oid>` users, `28:<guid>` bots, `4:<n>` PSTN, `8:teamsvisitor:<hex>` guests, `8:live:.cid.<hex>` personal, `48:<name>` virtual system threads (`/v1/threads` returns 400 for these), `tag:<id>` team tags.

## 3. Endpoints by feature

Chat service base `CS` = `https://<geo>.ng.msg.teams.microsoft.com` (or `https://teams.microsoft.com/api/chatsvc/<geo>`); all `/v1/...` paths are relative to it. Auth SKYPE unless noted. "Known" = already in kelma's stated baseline or purple-teams.

### 3.1 Presence (get / set / status message / OOO / work location)
Base `PB` = `https://presence.teams.microsoft.com/v1` (alias `https://teams.microsoft.com/ups/<geo>/v1`, which accepts the main bearer, Jezza §9.34; consumer: `https://teams.live.com/ups/global/v1` with `x-skypetoken` and `x-ms-client-consumer-type: teams4life`). Auth: **PRES** (all writes); reads also work with SPACES + `x-skypetoken` (teams-lite). Required client headers on subscribe/endpoint calls: `x-ms-client-user-agent: Teams-V2-Web` (or `Teams-V2-Desktop`), `x-ms-correlation-id: <uuid>`, `x-ms-client-version: 1415/26091712213`, plus `x-ms-endpoint-id` and `x-ms-client-type: cdlworker` on subscribe (the service answers 400 naming whichever is missing).

| Op | Request | Notes / source |
|---|---|---|
| Get (batch) | `POST PB/presence/getpresence/` body `[{"mri":"8:orgid:<oid>"},...]` (650/request purple+rusty, 200 ups, 50 better-teams) | Answer `[{mri, status, etag, presence:{availability, activity, lastActiveTime, note:{message,expiry}, calendarData:{isOutOfOffice, outOfOfficeNote:{message}}, sourceNetwork, workLocation?}}]`. Known. rusty `presence/lookup.rs`, teams-lite `teams_presence.rs`. **Beyond purple-teams:** `note` (status message), `calendarData.isOutOfOffice`, `workLocation{location,locationSource}` fields |
| Subscribe push | `POST PB/pubsub/subscriptions/<endpointId>` body `{"trouterUri":"<surl>unifiedPresenceService","shouldPurgePreviousSubscriptions":true,"subscriptionsToAdd":[{"mri":"8:orgid:<oid>","source":"ups"}],"subscriptionsToRemove":[]}` | Known; note the `"source":"ups"` field and `purge` only on first chunk (200/chunk). Pushes arrive on trouter as requests to `.../unifiedPresenceService` |
| Set status | `PUT PB/me/forceavailability/` body `{"availability":"Available"\|"Busy"\|"DoNotDisturb"\|"BeRightBack"\|"Away"\|"Offline"}`; `Offline` adds `"activity":"OffWork"`; optional `"desiredExpirationTime":"<ISO ms Z>"` (duration) | rusty `presence.rs`, better-teams `UnifiedPresence.swift`, teams-for-linux, mautrix `status.go`. Known (purple), but **expiry** and the exact value set are new |
| Clear forced status | `PUT PB/me/forceavailability/` **with no body** | rusty-teams. teams-lite found every `DELETE` spelling refused (401). mautrix instead uses Graph `POST /me/presence/clearUserPreferredPresence` (GRAPH) |
| Status message | `PUT PB/me/publishnote` body `{"message":"<html-escaped text>[<pinnednote></pinnednote>]","expiry":"9999-12-31T23:59:59.999Z"}`; empty `message` clears | Known. **New:** suffix `<pinnednote></pinnednote>` = "Show when people message me"; `expiry` choosable |
| Register this device | `PUT PB/me/endpoints/` body `{"id":"<endpointId>","availability":"Available","activity":"Available","activityReporting":"Transport"\|"Direct","deviceType":"Desktop"\|"Web"}`; `DELETE PB/me/endpoints/<id>` | Known (purple). teams-lite: registering an endpoint with `Available` is how to "appear Available" while no other client runs, and `DELETE .../endpoints/{id}` cleanly reverts (unlike forceavailability) |

### 3.4 Mentions (sending)
Two synchronized parts are required; name-only HTML does not notify (xteams, verified live, edits **replace** `properties` so omitting mentions on an edit clears them).
* `content` (messagetype `RichText/Html`): `<span itemtype="http://schema.skype.com/Mention" itemscope="" itemid="0">Name</span>` (Jezza/ic3 verified Teams web markup as `<readonly class="skipProofing" itemtype="http://schema.skype.com/Mention" spellcheck="false"><span itemtype="http://schema.skype.com/Mention" itemscope itemid="N">Name</span></readonly>`); `itemid` 0-based in document order, reply-quote blocks skipped.
* `properties.mentions` = **a JSON array encoded as a string**: `[{"@type":"http://schema.skype.com/Mention","itemid":0,"mri":"8:orgid:<oid>","mentionType":"person","displayName":"Name"}]`. Verified `mentionType` values: `person` (mri `8:orgid:`), `channel` (mri = the mentioned channel's own `19:...@thread.tacv2`), and `team` seen in Teams web sends (Jezza). Broadcast `@channel/@team/@everyone`: better-teams emits `<at id="0">channel</at>` with `properties.mentions` `[{"itemid":...,"mentionType":...,"displayName":...}]` (its own shape, not live-verified in the file I read) - treat as unconfirmed.
* Tag mentions use MRI `tag:<tagId>` (m0nkmaster).
* Receiving: mentions arrive in `properties.mentions` as an array or a JSON string; both forms must be parsed (Maxim, Jezza §9.23).
* Candidate resolution for `@name` in the composer: substrate People suggestions (3.2); channels from the conversation list or `GET /api/csa/<geo>/api/v2/...` (xteams: CSA `users/me/updates` returns only a partial roster).
* Roster for the @-list inside a chat: thread members (3.3). Channels expose no roster, so fall back to people who have posted (teams-lite).

### 3.6 Saved messages ("Save this message")
Server-side (not local-only; better-teams implements it locally, rusty and m0nkmaster use the real endpoint).
* Save/unsave: `PUT /v1/users/ME/conversations/<conversationId>/rcmetadata/<rootMessageId>` body `{"s":1,"mid":<messageId>}` (`s:0` to unsave). `rootMessageId` equals `messageId` in chats and for channel top-level posts, and is the parent post id for a channel reply; `mid` is always the message being saved. Answer `{"conversationId","rootMessageId","rcMetadata":{"lu":<ms>,"s":1}}`. Sources: rusty `saved.rs`, m0nkmaster `API-REFERENCE.md` (live-verified).
* List: `GET /v1/users/ME/conversations/48:saved/messages?view=msnp24Equivalent&pageSize=200&startTime=1`. Each item is a stub whose `properties.activity` (object **or** JSON string) has `activityType:"savedMessage"`, `sourceMessageId`, `sourceThreadId`, `sourceReplyChainId`, `sourceUserId`, `sourceUserImDisplayName`, `messagePreview`, `activityTimestamp`, `sourceThreadTopic`; `clumpId`/`secondaryReferenceId` = `T_<conv>_M_<msgId>` also present.
* Per-message `properties.rcmetadata`/`rcMetadata` carries the saved flag on the message itself.

### 3.7 Pinned messages
Two server mechanisms exist; the **CSA pinbar** is what current Teams uses (rusty-teams); the older **thread property** is what better-teams uses.
* CSA pinbar (rusty `pins/pinbar.rs`): `GET https://teams.cloud.microsoft/api/csa/<geo>/api/v1/chats/<chatId>/pinbar` returns `children[]` of `{type:"pinmsg"|"folder", pinBarItemId, pinnedMessageProperties:{messageId, pinnedDateTime}, children[]}` (pinned messages can live in folders); pin = `POST .../pinbar` body `{"pinbarId":"<chatId>","pinbarItemType":"pinmsg","pinbarItemId":"<msgId>","pinbarParentItemId":"","pinbarOperation":"add","pinbarItemPosition":0,"pinnedMessageProperties":{"messageId":"<msgId>","rootMessageId":"<msgId>"}}`; unpin = `DELETE` same URL, `"pinbarOperation":"remove"`, `pinbarParentItemId` = folder id if inside one. Auth: CSA bearer only.
* Pinned **channel posts** (rusty `pins/posts.rs`): `GET CSA/api/v1/teams/<teamThreadId>/channels/<channelId>/pins?pageSize=N` (paged by request header `x-ms-continuation`, response carries `continuationToken`), pin `POST .../posts/<postId>/pin` (no body), unpin `DELETE` same URL; only root posts can be pinned while `enablePinMessageV2` is off. These routes need CSA bearer **plus** `x-skypetoken` and `x-csendpoint: <chatService host>` (rusty's `SkypeTokenTransport`).
* Thread property (better-teams): `PUT /v1/threads/<id>/properties?name=pinnedItems` body `{"pinnedItems":"[{\"itemId\":\"<msgId>\",\"itemType\":\"Message\"}]"}` (value is a JSON string of the whole list; read it back from `GET /v1/threads/<id>?view=msnp24Equivalent` `properties.pinnedItems`). Round-trips, works for everyone in the chat; author did not confirm it matches what the Teams client displays.
* Graph `GET /chats/{id}/pinnedMessages` needs `Chat.Read` (403).

### 3.15 Calling / NGC signalling
Documented in depth by **eisbaw/ost** (`src/calling/signaling.rs`, MIT), **rusty-teams** (`crates/calling`, MIT), **teams-lite** (`NATIVE-CALLING.md`, no licence; derived from the web client JS bundle `calling-pluginless-<hash>.js`, `config-prod-<hash>.js`), **mautrix-teams** (`pkg/msteams/calls.go`, AGPL; verified audio both directions, video and screen share, meetings, 1:1 incoming/outgoing) and the mautrix OpenAPI (`/epconv`, `/cpconv`, `/add`, `/addParticipant`, `/updateEndpointState`, `/updateMediaDescriptions`, `/applyChannelParameters`, `/admit`, `/searchParticipants`, `/leave`, `/answer`, `/attach`, `/accept`, `/reject`, `/subscribe/{id}/{seq}`).
Condensed protocol:
1. **Second trouter registration for calling** (`appId: NextGenCalling`, `templateKey: DesktopNgc_2.5:SkypeNgc`, path `<surl>NGCallManagerWin`; ost registers `TeamsCDLWebWorker`, `SkypeSpacesWeb`, and `NextGenCalling` against `POST https://teams.microsoft.com/registrar/prod/V2/registrations`, header `X-Skypetoken`; web client calling stack: `pnhTemplate SkypeSpacesWeb_2.6`, own trouter `wss://go.trouter.teams.microsoft.com/v3/c`, ttl 3600).
2. **Place**: one `POST regionGtms.calling_conversationServiceUrl` (`https://api-<geo>.flightproxy.teams.microsoft.com/api/v2/epconv`) with IC3 bearer + headers above. Body: `conversationRequest{subject, roster{type:"Delta",rosterUpdate:<cb>}, properties{allowConversationWithoutHost,enableGroupCallEventMessages,...}, links{conversationEnd, conversationUpdate, localParticipantUpdate, addParticipantSuccess, addParticipantFailure, receiveMessage,...}}`, `groupChat{threadId,messageId}`, `participants{from{id,displayName,endpointId,participantId,languageId}, to[...]}`, `endpointCapabilities` (73463), `clientEndpointCapabilities` (9336554), `endpointMetadata`, `meetingInfo`, `endpointState`, `callInvitation{callModalities, links{progress,mediaAnswer,acceptance,redirection,end}, mediaContent{blob:<SDP>, contentType:"application/sdp-ngc-1.0"}}`. **No `payload` envelope** (teams-lite wasted days on this: 400 with empty body). Callback URLs are built on the trouter surl: `<surl>callAgent/<sessionId>/<hash8>/<call|conversation>/<action>/`. Exactly one credential header (`Authorization` or `X-Skypetoken`), never both; no `api-version` header.
3. Responses hand back **links** (`conversationController`, `addParticipant`, `leave`, `keepAlive`, `mute`, ...); every later step POSTs to a link. Requests to `*.cc.skype.com` / `*.conv.skype.com` are routed via `https://api.flightproxy.teams.microsoft.com/api/v2/ep/<host>/<path>`.
4. **Incoming**: trouter pushes a `callInvitation` with `links.acceptance`; accept = `POST <acceptance>` `{"acceptedCallModalities":["Audio"],"endpointMetadata":{...}}` with `X-Skypetoken`; media answer to `mediaAnswer`; decline `rejection`; hangup `end`.
5. **Media**: stock WebRTC/ICE with SDES-SRTP or DTLS-SRTP, Opus/PCMU, `application/sdp-ngc-1.0` blob (ost has an SDP dictionary compressor). Relay credentials: `GET https://teams.microsoft.com/trap/tokens` (headers `api-version: 2`, `X-MS-Migration: True`, IC3 bearer or `x-skypetoken`) -> `{tokens:[{realm,username,password}], expires:604800}`; TURN at `gateway-<geo>.az.relay.teams.cloud.microsoft` (udp 3478, tcp/tls 443) or FlightProxy `api.flightproxy.teams.microsoft.com:3478`. ost guesses `POST https://api.flightproxy.teams.microsoft.com/api/v2/ep/relay/token`, which no HAR confirms.
6. Meetings: same `epconv` with `meetingInfo{tenantId, organizerId}`; roster/mute/lobby admit/spotlight/hand raise/captions/recording are all link-driven (rusty `signaling.rs`, `roster.rs`, `captions.rs`, `recording.rs`: recording and captions are **bot commands** POSTed to a URL in the roster).
7. Consumer accounts use `https://api.flightproxy.skype.com/api/v2/cpconv` with `conversationRequest.applicationType: TFL`.
Not covered anywhere: group-call ringing at scale, E2EE calls, PSTN dial-out (see gaps).

## 5. Gaps nobody has implemented (or only half)

Verified by grepping all cloned projects plus code search on the endpoint/keyword; "half" = parsing only or HAR-observed only.

1. **Voicemail** (list, audio, transcript, greeting): only `voicemail` target types inside `48:calllogs` are recognised (mautrix); no endpoint for the media/transcript is documented anywhere. `calling_callStoreUrl` always returned `[]`.
2. **Emergency calling / E911 / location**: no project, no capture, no keyword hit.
3. **PSTN dial-out/dial pad, call forwarding, simultaneous ring, delegates, shared line** (`calling_sharedLineOptionsUrl`, `userEntitlementService`): untouched. Only PSTN MRIs (`4:`) and `incoming_pstn_call` toast names appear.
4. **Server-side `msgsearch` service** (`regionGtms.search`, `.../msgsearch`): no client uses it; everyone uses substrate `searchservice/api/v2/query`.
