# emoji

## Overview
Static emoji table with search, shortcodes, `:name` autocomplete and skin tones. No network and no state: data is a checked-in generated table (`src/table.rs`, private) produced by the generator script `gen/gen.py` (a script, not a package). The public `teams` module holds Teams' own emoticon catalog (`data/teams-emoticons.tsv`, generated by `gen/teams.py` from the catalog the Teams web client loads, embedded with `include_str!` and parsed once on first use). The crate has no dependencies.

## Interface
- `Category {SmileysEmotion, PeopleBody, AnimalsNature, FoodDrink, TravelPlaces, Activities, Objects, Symbols, Flags}`, `Category::ALL: [Category; 9]`, `Category::label()` [lib.rs:Category].
- `Emoji {ch, name, keywords, category, skin_tones}` (`Debug, PartialEq, Eq`) [lib.rs:Emoji].
- `all() -> &'static [Emoji]` [lib.rs:all].
- `by_shortcode(code: &str) -> Option<&'static Emoji>` [lib.rs:by_shortcode].
- `search(q: &str, limit: usize) -> Vec<&'static Emoji>` [lib.rs:search].
- `autocomplete(text_before_cursor: &str) -> Option<(usize, Vec<&'static Emoji>)>` (usize is the byte offset of `:`) [lib.rs:autocomplete].
- `with_skin_tone(e: &Emoji, tone: u8) -> String` [lib.rs:with_skin_tone].
- `gen/gen.py`: `python3 -I crates/emoji/gen/gen.py [emoji-test.txt [annotations.json]]` regenerates `src/table.rs` [gen/gen.py].
- `teams::Emoticon {id, unicode, diverse, teams_only, description}` with `shortcuts()`, `keywords()`, `glyph(tone) -> String`, `key(tone) -> String`, `name(tone) -> String` [teams.rs:Emoticon].
- `teams::all()`, `by_id(&str)`, `by_shortcut(&str)`, `search(q, limit)` [teams.rs].
- `teams::split_tone(key) -> (&str, u8)`, `parse_key(key)`, `glyph_of_key(key) -> Option<String>`, `name_of_key(key) -> Option<String>`, `key_for_glyph(glyph) -> Option<String>`, `apply_tone(glyph, tone) -> String`, `tone_name(tone)` [teams.rs].
- `gen/teams.py`: `python3 -I crates/emoji/gen/teams.py [<emoticonAssetVersion> | <en-us.json>]` regenerates `data/teams-emoticons.tsv`; with no argument it reads the current `emoticonAssetVersion` from the Teams web config bundle [gen/teams.py].

## Invariants
- Table order is picker order (Unicode `emoji-test.txt` group order) and `Category::ALL` has the same order [lib.rs:all].
- `search` trims and lowercases the query; an empty query or `limit == 0` gives an empty vec. Ranking: exact shortcode or alias prefix first, then name prefix, then word or keyword prefix, then substring; ties keep table order [lib.rs:search, rank].
- Shortcodes are derived from the CLDR name: lowercase, runs of non-alphanumerics collapsed to `_`; the six Teams `ALIASES` (heart, like, laugh, surprised, sad, angry) take priority and do not fall through to name matching [lib.rs:shortcode_of, by_shortcode, ALIASES].
- `autocomplete` needs a `:` preceded by a non-alphanumeric char, at least two following chars that are alphanumeric or `_`, and returns at most 8 hits (`AUTOCOMPLETE_LIMIT`) [lib.rs:autocomplete].
- `with_skin_tone` returns `ch` unchanged unless `skin_tones` is set and `tone` is in 1..=5; the modifier is inserted after the first codepoint and a following U+FE0F is dropped [lib.rs:with_skin_tone].
- The table holds no skin-tone variant rows and only `fully-qualified` rows of the nine known groups [gen/gen.py:main].
- `table.rs` is generated; do not edit by hand [table.rs header, gen/gen.py].
- Lookups are linear scans; there is no index [lib.rs:by_shortcode].
- Teams keys: a reaction key is a catalog id, or `<id>-tone<n>` (n in 1..=5, light to dark) for a skin tone; `split_tone` accepts no other suffix [teams.rs:split_tone]. `Emoticon::key` adds a tone only to `diverse` emoticons; `glyph_of_key` applies a given tone to any emoticon whose glyph has a modifier base [teams.rs:Emoticon::key, glyph].
- `apply_tone` puts the modifier after every `Emoji_Modifier_Base` codepoint (Unicode 16 list in `MODIFIER_BASES`), drops a U+FE0F right after it, and leaves a handshake joined by ZWJ (people holding hands) untoned [teams.rs:apply_tone].
- `glyph` never returns the id or a `(code)`: a Teams-only animation shows its stand-in emoji from `gen/teams.py:TEAMS_ONLY`, or its description [teams.rs:Emoticon::glyph].
- `key_for_glyph`: a toned glyph maps to the first diverse emoticon with that glyph (`yes-tone2` for 👍🏼); an untoned one prefers the six named reactions, then catalog order (`like` for 👍); emoji the catalog lacks (flags) give None [teams.rs:key_for_glyph].
- Duplicate ids or shortcuts in the catalog: the first wins [gen/teams.py, teams.rs:CATALOG].

## Side Effects
- The crate itself: none (immutable static table) [lib.rs, table.rs:EMOJI].
- `teams` builds its index (a `LazyLock`) on first use; nothing else [teams.rs:CATALOG].
- `gen/teams.py` with no argument fetches teams.microsoft.com/v2/, the `config-prod-*.js` bundle it links and the catalog from statics.teams.cdn.office.net (60 s timeout), and always overwrites `data/teams-emoticons.tsv`.
- `gen/gen.py` with no arguments downloads `emoji-test.txt` (unicode.org) and CLDR annotations (raw.githubusercontent.com) with a 60 s timeout, and always overwrites `crates/emoji/src/table.rs`; it runs `main()` at import time [gen/gen.py].
