# teams-proto

## Overview
`teams-proto` is the unofficial protocol client library for the Microsoft Teams chat protocol. It is a single flat Rust crate: every module lives in `src/` and is declared `pub mod` in `src/lib.rs`. Protocol facts come from purple-teams (GPL-3.0) and from observing the Teams web client; every endpoint is internal and undocumented and can change without notice [lib.rs: module doc].

The crate follows one pattern throughout. Each feature module holds (a) pure request-body builders and response parsers over `serde_json::Value`, and (b) an `impl Client` block of async methods that send the request through the shared authenticated `Client`. Several modules only build a `graph::Write` or `user_settings::PlannedRequest` value and send nothing themselves.

The Interface lists below name the main public items of each module. The larger modules (`teams`, `card`, `onenote`, `planner`, `recaps`, `user_settings`, `global_search`) export many more parsers, body builders and `Client` methods than are named here.

Crate root re-exports: `Client`, `Session` (from `client`) and `Error`, `Result` (from `error`) [lib.rs].

## Invariants
- **Credential scoping.** `http::headers_for` returns only `User-Agent` for non-https URLs and for `Backend::Other`, so links in messages cannot leak a token [http.rs: headers_for]. `Client::request_raw_as` attaches an audience bearer token only to https URLs on that audience's own host and returns `Error::Protocol` otherwise [client.rs: audience_owns, request_raw_as]. AMS downloads refuse non-AMS URLs [ams.rs: is_ams_url, download_image; images.rs: fetch_ams]. `Session`, `Tokens`, `TokenResponse`, `SkypeToken`, `AppToken` and `TokenCache` Debug output never prints token values [client.rs, http.rs, auth.rs, broker.rs].
- **Token refresh.** A token is stale when expiry <= now + 300 s, measured with wall-clock `SystemTime` [client.rs: REFRESH_MARGIN; broker.rs: MARGIN]. A 401 is retried exactly once with a fresh token [client.rs: request_raw_as]. Only GET/HEAD are resent after a transport error, at most once; writes are never resent [client.rs: resend_safe].
- **Audience validation.** `Audience::app` accepts only `api://` or `https://` resources with a restricted character set, to prevent scope smuggling [broker.rs: Audience::app]. `Audience::sharepoint` requires a single-label `*.sharepoint.com` host [broker.rs: Audience::sharepoint].
- **Identity MRIs.** Search, people, shared-items and anchor-mailbox calls require an `8:orgid:<oid>` self MRI and return `Error::Protocol` otherwise; Substrate answers 200 with empty results unless `x-anchormailbox` names the caller's own mailbox [people.rs: anchor_mailbox, oid_of_mri; global_search.rs; search.rs; views.rs].
- **Idempotent sends.** Send helpers take a caller-chosen `client_message_id`; reusing it on retry must not post a second message, so outbox code must reuse the same id [chatsvc.rs: send_message_as; mentions.rs: outgoing_body; delivery.rs; card_send.rs; voice.rs; video_clip.rs]. Card ids derive deterministically from the client message id [card_send.rs: cards_property; voice.rs: card_id].
- **Wire-format quirks callers must keep.** `properties.cards`, `properties.mentions`, `properties.files` and `qtdMsgs` are JSON-encoded strings, not arrays [card_send.rs, mentions.rs, files.rs, chatsvc.rs, delivery.rs]. Follow flags are the numbers 1/0 (a JSON `true` is refused with 400) [posts.rs: follow_body]. An edit replaces `properties`, so an edit must resend mentions [mentions.rs: edit_body_with_mentions].
- **Parsing is lenient, writing is strict.** Parsers skip entries missing required ids rather than failing [csa.rs, tags.rs, planner.rs, onenote.rs, lists.rs, workflows.rs, tenants.rs]. A channel without `displayName` is named "General" only when `isGeneral` is true; any other nameless channel gets an empty name [csa.rs:parse_snapshot]. `Error::status` truncates bodies to 400 characters; `From<reqwest::Error>` drops the URL, and `Error::Http`'s `Display` appends the whole cause chain (`http_chain`) [error.rs].
- **Log hygiene.** Log lines that carry URLs or server text go through `logsafe::url` and `logsafe::text`, so pre-signed query strings and token-like runs stay out of the log file [logsafe.rs].
- **Read-only or disabled paths.** The private constant `STORYLINE_POST_DISABLED` in `engage.rs` is `true`, so `Client::post_storyline` always errors [engage.rs:STORYLINE_POST_DISABLED]. `sections` implements no write calls (module doc), and `lists` adds and edits items but never deletes one [sections.rs: module doc; lists.rs: module doc]. Several modules document their write paths as UNVERIFIED against a real account (`photo`, `video_clip`, `channel_tabs`, `workflows`, `recaps` MCPS host, `mt::Client::team_picture`) [module docs].
- **Size caps.** Downloads are capped by caller `max_bytes` (`DOWNLOAD_TOO_LARGE` error prefix); full images 50 MiB [images.rs: MAX_FULL_IMAGE_BYTES]; AMS images 20 MiB [ams.rs: MAX_IMAGE_BYTES]; profile photos 4 MiB [photo.rs: MAX_PHOTO_BYTES]; avatar downloads 4 MiB [mt.rs]; gunzip output 32 MiB [trouter.rs: gunzip]; uploads above 4 MiB use an upload session [files.rs: SIMPLE_UPLOAD_MAX].
- **Privacy of third-party services.** Translation and link preview send message content or links to Microsoft services, so callers translate or preview only when the user asks or settings allow [translate.rs: module doc; urlpreview.rs: preview]. `urlpreview::fetch_image` accepts only urlp service hosts and caps downloads at 5 MiB [urlpreview.rs: is_service_url, fetch_image]. `translate::MAX_BATCH` is 30 message ids per call [translate.rs: MAX_BATCH].
- **Activity goes over the trouter.** The presence endpoint is registered with `activityReporting: "Transport"` [presence.rs: endpoint_body], so the service takes the user's activity from the trouter's `user.activity` event: sent with the current value of `set_user_active` on every connect and again on every change once authenticated [trouter.rs: USER_ACTIVE, connect_once]. Logged at info (`trouter: connected, user activity sent`, `trouter: user activity sent`).
- **Trouter registration order.** `TeamsCDLWebWorker` must be registered last because it delivers chat events [trouter.rs: register].

## Side Effects
- **Network (HTTPS).** All `Client` methods perform requests to Microsoft hosts: chat service (`{chat_service}/v1/...`), middle tier (`{middle_tier}/beta/...`), CSA (`teams.microsoft.com/api/csa/api/v1|v2|v3`), presence UPS, AMS (`*.asm.skype.com`, `as-prod.asyncgw.teams.microsoft.com`, and the per-region twins `<region>-prod.asyncgw.teams.microsoft.com` that image and media downloads fall back to on a connection failure), Graph (`graph.microsoft.com`), Substrate (`substrate.office.com`), SharePoint, Power Automate (`api.flow.microsoft.com`), Viva Engage (`api.yammer.com`, `engage.cloud.microsoft/graphql`), Delve Loki, Teams provisioning (`teams.microsoft.com/fabric/...`), MCPS, and the Entra authority `client_info::AUTHORITY` for token minting [per-module].
- **WebSocket and timers.** `trouter::run` opens a socket.io v0 WebSocket, registers with `teams.microsoft.com/registrar/prod/V2/registrations`, pings every 30 s, re-registers on a timer, and reconnects with 1 to 60 s backoff until the receiver is dropped [trouter.rs: run, connect_once]. `create_private_channel` polls up to 15 times at 2 s intervals [teams.rs]. Device-code polling sleeps between polls [auth.rs: poll_device_code].
- **Disk.** `images::save_image` creates directories and writes files with `create_new` semantics (never overwrites) [images.rs: save_image]. No other module touches disk or environment variables.
- **Process-global state.** `client::install_crypto_provider` installs the rustls `ring` default provider; reqwest is built with `rustls-no-provider`, so a `reqwest::Client` built before the call panics [client.rs:install_crypto_provider, Cargo.toml]. `ams::PREFER_ASYNCGW` is a process-wide `AtomicBool` set once an `asm.skype.com` address failed while its asyncgw twin answered, so later downloads try the twin first; `download_image`, `download_media` and `images::fetch` (through `fetch_ams_routed`) retry on the twin only after a connection failure, not an HTTP error [ams.rs:PREFER_ASYNCGW, ams_attempts, ams_remember; images.rs:fetch_ams_routed]. `Client` shares token state through `Arc<tokio::sync::Mutex<State>>` and a per-audience `TokenCache` [client.rs: State; broker.rs]. `Client::tenant_id` reads the `tid` claim of the Spaces token [people.rs].
- **Clock and randomness.** Many send paths read the wall clock via `time::now_ms` for client message ids and generate UUID v4 values (`new_epid`, correlation ids) [time.rs; client.rs; presence.rs; search.rs].
